# 下载中断时，用本地ZIP安装

适用日志：`Failed to download file: .../archive/HEAD.zip`、`Server disconnected without sending a response`、`httpx.RemoteProtocolError`。

## 1. 先区分日志中的阶段

安装分为下载代码、检查依赖、加载插件。仓库ZIP下载中断发生在第一步，插件的`main.py`还没有运行，不能靠修改插件里的网络请求来修复AstrBot本体的下载连接。

旧版v1.0.0另有Pillow版本上限冲突，已在v1.0.1修复，v1.0.2保留该修复。一份长日志可能同时保留旧安装的依赖错误和随后一次安装的下载错误。应按最后一次操作的错误处理，不能因为旧日志还在，就认定新版本仍带着旧依赖。

## 2. 准备最新完整ZIP

如果你在交付聊天中拿到了`astrbot_plugin_wows_captain-v1.0.2.zip`，直接下载到自己的电脑。也可以在自己的电脑浏览器打开仓库：

<https://github.com/brochure325/1>

1. 点击文件列表上方的绿色`Code`按钮。
2. 点击`Download ZIP`。
3. 等待下载完成，文件可能叫`1-main.zip`或`1-HEAD.zip`，这不影响安装。
4. 下载结果必须是真正ZIP，不能是保存下来的GitHub网页。
5. 不要解压再挑单个文件上传；保留完整ZIP。

电脑浏览器下载成功和AstrBot服务器能否下载，是两条不同的网络路径。把已经下载好的文件上传给管理面板，可以跳过服务器访问GitHub仓库下载地址的步骤。

## 3. 在AstrBot管理页面上传

1. 在浏览器打开你平时使用的AstrBot管理页面。
2. 点击左侧`插件`，进入已安装插件页面。
3. 如果已有“战舰世界舰长助手”卡片，先记录版本及加载状态；无需删除绑定和快照数据。
4. 点击`安装插件`或右下角加号。
5. 切换到`从文件安装`；该入口有时称`上传插件`。
6. 点击选择文件，从电脑的“下载”文件夹选择刚才的ZIP。
7. 点击上传/安装，等待上传、解压、依赖检查和加载结束。
8. 本插件兼容AstrBot 4.29.1，不需要勾选“忽略版本检查”或关闭核心依赖保护。
9. 成功后在插件列表确认名称和开关，再向机器人发送`/wows 帮助`。
10. 发送`/wows 状态`，最新版完整包应显示`1.0.2`。

不要在“从链接安装”里填写你电脑上的ZIP路径。要走的是文件选择和上传流程。

## 4. 已有失败插件或旧安装目录时

AstrBot4.29.1的文件安装路径支持识别同一插件并更新。优先直接上传新版ZIP；更新过程不要主动删除整个插件数据目录。

若面板仍提示同名插件/目录冲突，先记录它给出的实际路径，确认属于本插件。请按管理面板提供的同插件更新或失败安装清理流程处理，不要盲目删除`/opt/astrbot/data`。该目录还可能保存模型配置、其它插件和聊天数据。

本插件持久化数据在`data/plugin_data/astrbot_plugin_wows_captain`，配置通常在`data/config`。重新安装代码与删除持久化数据是不同操作；需要恢复数据时，先停服务并做自己的私有备份。

## 5. 如果上传后仍报错

- **仍然显示旧`Pillow<13`**：说明实际加载的代码包或目录仍是旧版；核对ZIP内`requirements.txt`应为`Pillow>=11.2.1`，没有`<13`。不要降级Core的Pillow13.0.0。
- **仍然请求`archive/HEAD.zip`**：核对是否切换到了“从文件安装”；这通常说明操作仍走仓库链接下载。
- **ZIP格式错误/缺少metadata.yaml**：重新取得完整仓库ZIP，不要上传网页HTML、单个Python文件或只含说明文档的压缩包。
- **上传本身超时或HTTP413**：检查管理面板前面的反向代理上传限制。此项目完整包约几百KB，正常情况下不需要开放很大的文件限制；以实际包体大小为准。
- **pip源超时**：ZIP上传不提供独立的Python运行环境。请让AstrBot实际使用的环境能取得依赖，或沿用Core中满足要求的现有版本。
- **已显示插件加载成功，但没有游戏查询结果**：此时再检查WG应用ID、聊天模型、浩舰连接等功能配置，按主安装指南逐项验收。

## 6. 验证范围

交付ZIP会检查压缩包完整性、必需文件和元数据，并用AstrBot4.29.1的归档校验/解压方法验证目录结构。本地接口测试与这些检查不能替代你实际服务器的安装结果。

这里的文件安装不要求服务器先从GitHub取代码。游戏查询仍需要服务器能访问对应的WG或浩舰数据服务，模型分析仍需要所选模型可用。
