# 知识库、赛事记录和专家教学导入

## 1. 现有内容与工作方式

内置完整攻略是 `knowledge/advanced_guide.md`。`sources_and_events.json` 保存来源目录、官方赛事规则与结果、赛事站比赛卡片字段，以及能够核对的教学摘要。插件把问题与标题、标签、中文双字词和正文匹配，只给模型传入相关片段；这是检索，不会重新训练模型。

初版赛事包含KOTS XV、XVI及Warship Masters 2024，并记录一场KOTS XVI EU比赛卡片。它不是所有届次的完整比赛数据库。教学包含官方机制导航和iChaseGaming本人频道公开简介能够支持的主题摘要；未取得的字幕和未观看录像，不标成已经消化的专家课件。

`updated_at` 是资料核对日期，不代表比赛日期。`version` 写适用游戏版本或赛制。`claim_type` 可为：

- `fact`：来源直接支持的事实，例如赛制、比分或冠军。
- `teaching_summary`：原作者教学中实际核对的简短摘要，注明只读到简介还是观看过对应片段。
- `replay_observation`：你已观看录像的直接观察，需链接和时间戳。
- `tactical_inference`：你据观察提出的战术推断，不能写成赛事官方事实。

## 2. 准备一个可检查的文件

1. 在电脑新建一个文件夹，例如 `C:\WoWSNotes`。
2. 打开记事本。
3. 粘贴下面的空模板，并用你亲自核对的资料替换文字。
4. “文件→另存为”，选择该文件夹。
5. 文件名写 `my_replay.json`，保存类型选择“所有文件”，编码选UTF-8。
6. 确认扩展名为 `.json`，没有变成 `.json.txt`。资源管理器可在“查看→显示→文件扩展名”开启显示。

```json
{
  "schema_version": 1,
  "reviewed": false,
  "sources": [
    {
      "id": "my-replay-source",
      "title": "填写原始赛事和对局标题",
      "url": "填写真实原始录像链接",
      "publisher": "填写赛事方或原作者",
      "checked_at": "2026-10-28"
    }
  ],
  "entries": [
    {
      "id": "my-replay-unique-id",
      "title": "填写你实际观察的问题",
      "text": "填写真实时间点、观察事实和版本；把推断另写一条。",
      "claim_type": "replay_observation",
      "url": "填写真实原始录像链接",
      "source_ids": ["my-replay-source"],
      "updated_at": "2026-10-28",
      "version": "填写录像实际版本与赛事规则",
      "tags": ["复盘", "驱逐舰", "视野"]
    }
  ]
}
```

模板中的链接是待填写文本，原样导入会被拒绝。不要把示例日期当成录像日期。每条正文最多30000字符，建议一个决策主题一条，保留精确但简短的摘要，不复制整段付费教程或全部字幕。

## 3. 录像和赛事应记哪些字段

赛事级记录先写名称、届次、区域、开始与结束时间、时区、游戏版本、参赛资格、人数、等级、禁用舰种、预算和选图规则。仅有赛程时，不填最终冠军。地区赛与国际赛分别建条目。

对局级记录写原始比赛链接、队伍、赛制阶段、系列赛总分、单局地图、双方分数和结束时间。来源没有说明结束原因时，不根据分数猜测。官方比分也不能证明哪位玩家意识更好。

录像观察写准确播放时间和游戏内剩余时间，记录双方可见阵容、船位、血量、已知消耗品、视野来源、点数与时间。把“某驱逐转向撤离”作为观察，把“为了保留雷达真空期的争点能力”作为推断；没有队内语音或明确说明，不能说你知道队伍的真实意图。

专家教学写作者姓名/频道、原视频标题、发布日期、链接、你确实核对的片段、短摘要和适用条件。没有观看时只保存入口或简介摘要，不伪造时间戳、原话与冠军资历。

## 4. 找到 AstrBot 使用的 Python 与插件目录

最容易的是在维护AstrBot的终端操作。已经有源码部署时，先进入AstrBot项目目录并使用它的虚拟环境。桌面版通过客户端提供的数据目录/终端入口找到实际运行环境，不要随意给系统另装一个Python后以为插件会用它。

插件代码目录通常在 `AstrBot/data/plugins/` 下；仓库名为 `1`，实际文件夹可能是 `1`，请确认里面有 `main.py`、`metadata.yaml` 和 `core`。不要假设目录一定等于插件展示名。

持久化知识建议存放在：

```text
AstrBot/data/plugin_data/astrbot_plugin_wows_captain/knowledge
```

它在插件代码目录之外，更新插件时不会跟着替换。下面命令中的Python与目录都要替换成你实际部署的路径。

## 5. Windows 导入

1. 在资源管理器打开实际插件代码文件夹。
2. 点击地址栏，输入 `powershell`，按回车。
3. 确认窗口当前目录是插件根目录。
4. 确定要使用的AstrBot Python路径，例如源码虚拟环境 `C:\AstrBot\.venv\Scripts\python.exe`；这只是示例，桌面版实际位置可能不同。
5. 先运行帮助，确认工具能加载：

```powershell
& 'C:\AstrBot\.venv\Scripts\python.exe' -m core.knowledge --help
```

6. 人工核对来源、版本、摘要与授权；确认之后运行：

```powershell
& 'C:\AstrBot\.venv\Scripts\python.exe' -m core.knowledge --root 'C:\AstrBot\data\plugin_data\astrbot_plugin_wows_captain\knowledge' --import-file 'C:\WoWSNotes\my_replay.json' --reviewed
```

7. 输出应包含一个 `imported_...json` 路径和已载入条目数。失败会解释缺失标题、无效链接、JSON格式或其它问题；先修正源文件再重新导入。
8. 在AstrBot插件页重载本插件，让内存索引读入新文件。
9. 向机器人发送 `/wows 攻略 你的条目中特有的关键词`。
10. 检查返回是否含你新增的标题和正确来源。

## 6. Linux / Docker 导入

在Linux源码部署中，从插件根目录执行：

```bash
python -m core.knowledge --root /path/to/AstrBot/data/plugin_data/astrbot_plugin_wows_captain/knowledge --import-file /path/to/my_replay.json --reviewed
```

Docker用户先把源文件放进已挂载的私有 `data` 目录，例如宿主机 `data/imports/my_replay.json`。在容器内找到实际插件目录后，执行：

```bash
docker exec -it astrbot sh
cd /AstrBot/data/plugins/实际插件文件夹
python -m core.knowledge --root /AstrBot/data/plugin_data/astrbot_plugin_wows_captain/knowledge --import-file /AstrBot/data/imports/my_replay.json --reviewed
exit
```

`实际插件文件夹` 需要替换，不是照抄的目录名。导入完成后重载插件。源文件和包含个人复盘的知识库应保存在自己的持久化目录，不能自动上传公开仓库。

## 7. Markdown 笔记

也支持本地 `.md` 文件，用 `##` 划分主题。未经特殊元数据标注的笔记，通过导入工具显式审核后才转换进持久化知识；普通文件直接丢进知识目录不会自动当可靠证据。机制事实、教学与录像观察推荐JSON格式，以便每条记录保留来源、类型和版本。

## 8. 维护与排错

- **检索没出现新内容**：检查实际输出目录，确认重载过插件；用独有关键词查找。一般问题会优先匹配更相关的内置条目。
- **标题相同但内容冲突**：先区分版本与赛制，不要直接覆盖旧记录；把适用范围写进标题和 `version`。
- **状态显示载入异常**：检查JSON逗号、引号、日期和URL；`sources`是对象列表，`source_ids`是字符串列表。
- **删除旧资料**：先备份持久化知识目录，再删除对应的明确文件并重载；不要删除整个AstrBot的data目录。
- **同一文件重复导入**：文件内容相同会得到相同内容哈希文件名。内容变化会产生新文件，更新时应人工检查并移除已过时的旧条目。

导入工具只读本地文字文件，不会自动下载视频、登录课程网站或获取付费字幕。想持续提升回答质量，最有效的是补充版本清楚、观察精确、结论可复核的材料。
