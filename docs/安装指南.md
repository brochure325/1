# 从零安装战舰世界舰长插件

适用项目：`astrbot_plugin_wows_captain`  
GitHub 仓库：<https://github.com/brochure325/1>  
要求：AstrBot **4.29.1 或更新版本**；如果你自己维护 Python，需要 **Python 3.12 或更新版本**。  
本文核对日期：2026-10-28。

这份指南按“第一次安装机器人”的顺序写。已经有 AstrBot 的用户可以从第 3 节开始；已经能正常与机器人聊天的用户可以从第 5 节开始。先完成一个最简单的查询，再逐项启用分析、图片和主动讨论，出现问题会更容易定位。

AstrBot 和消息平台的界面会更新。本文使用的是核对时的菜单名称，个别版本可能把“机器人”称为“消息平台”，把“创建”称为“新增”；请按同一功能寻找，不需要为了按钮文字不同重新安装。本文提供具体输入与验证方法，没有用未实测的截图冒充你的电脑画面。

## 1. 安装前，先知道每个部分负责什么

你最终会用到三个主要部分。

**AstrBot** 是机器人本体，负责登录管理页面、接收消息、连接模型和运行插件。**本插件** 负责战绩、图表、舰船资料、战舰世界资料检索和讨论规则。**消息平台连接** 负责让 QQ、Discord、Telegram 等聊天软件把消息送到 AstrBot，再把回答发回去。

插件装好，不代表 QQ 会自动登录；模型配好，也不代表官方游戏 API 的应用 ID 已经配好。我们会分开验证。

使用国际服公开战绩，需要你申请自己的 Wargaming `application_id`。它是你的应用访问标识，不是战舰世界账号密码。基础查询不要求你有 Kokomi 水表服务账号；若要使用 Kokomi 原有的完整命令、服务端近期历史、服务器排行榜或它独有的图表，则另按仓库里的桥接文档配置对应服务与权限。

使用自然语言攻略、战绩分析和自动插话，需要 AstrBot 已接入可用的聊天模型。识别玩家发来的图片，需要支持图片输入的视觉模型。模型厂商可能按用量收费，价格与额度以你自己选的服务商控制台为准；不要把“安装免费插件”理解成“调用所有模型和第三方服务免费”。

先准备这些东西：

- 一台能联网、能持续运行的电脑。Windows 新手可以优先走桌面版；关机或休眠后本机机器人也会停止服务。
- 一个用于管理 AstrBot 的浏览器，例如电脑里已有的 Edge 或 Chrome。
- 你要查询的国际服游戏昵称及服务器。`asia` 为亚服、`eu` 为欧服、`na` 为美服，英文均用半角。
- 你本人可登录 Wargaming 开发者网站的国际账号。国服账号不一定能直接登录国际开发者门户。
- 如果需要 AI 回答，准备你选用的模型服务地址、API Key、可用的模型名称。
- 如果接 QQ，准备你要使用的消息平台接入方式；QQ 官方机器人与普通 QQ 个人号的接法不同。

把登录密码、模型 Key、浩舰 Cookie 和桥接 Token 放在自己的私有设置中，不要发到群里或 GitHub。本文的命令示例都不要求你在聊天中公开凭证。

## 2. Windows 第一次安装 AstrBot

如果你已经打开 AstrBot 管理页面，可以跳到第 3 节。

### 2.1 下载正确安装包

1. 打开浏览器。
2. 单击最上方的地址栏，输入 <https://github.com/AstrBotDevs/AstrBot-desktop/releases>，按回车。
3. 确认页面仓库所有者是 `AstrBotDevs`，仓库名是 `AstrBot-desktop`。
4. 找到你准备安装的正式版本。展开该版本下面的 `Assets`；若默认只展示几个文件，单击“显示全部资源”。
5. 找到 Windows 对应安装包。常见后缀是 `.exe`。不要下载 `Source code (zip)` 或 `Source code (tar.gz)`，这两项是源码，不是桌面安装程序。
6. 按电脑架构选包：普通 Intel/AMD Windows 电脑通常选 x64；ARM 电脑应选项目提供的 ARM64 包。如果不确定，右键 Windows“开始”按钮，进入“系统”，看“系统类型”。
7. 单击对应文件，等待浏览器下载完成。

你应当看到浏览器下载列表里出现安装文件。若下载失败，先检查网络；不要为了安装插件随意关闭系统安全软件，也不要把不明镜像站的安装包当成官方包。

### 2.2 安装与第一次启动

1. 打开浏览器右上角“下载”列表，找到刚才的安装包。
2. 单击文件打开；若浏览器要求“在文件夹中显示”，先进入文件夹再双击。
3. 按安装向导选择安装位置，完成安装。文件名和向导的具体按钮可能随版本变化，以官方发布说明为准。
4. 从 Windows“开始”菜单打开 AstrBot 桌面客户端。
5. 按客户端的初始化向导完成机器人模式/运行环境的准备。新手不需要单独再安装一套 Python 来“给桌面版补环境”。
6. 等待客户端显示运行状态。第一次可能需要下载运行资源，等待结束后再继续，避免重复启动多个实例。
7. 在客户端里进入机器人管理界面。若它展示了 WebUI 地址，用浏览器打开客户端实际提供的地址。
8. 如果首次登录需要账号密码，使用当前启动日志或客户端显示的初始凭据，不要照搬网上旧教程的固定默认密码。
9. 登录后先修改管理密码，并保存在自己的密码管理工具或私密笔记里。

你应当看到包含“机器人/消息平台”“模型提供商”“插件”“数据与日志”等入口的管理页面。如果你只看到聊天窗口，先寻找客户端的机器人模式/管理入口；暂时不要安装本插件到另一个不相关的聊天客户端中。

### 2.3 确认版本与正常运行

1. 在客户端“关于”、设置或启动日志里查看 AstrBot 核心版本。
2. 本插件要求核心版本至少为 `4.29.1`；桌面客户端版本号和 AstrBot 核心版本号不一定相同。
3. 核心版本不足时，使用客户端自己的更新入口或官方说明更新核心，再重新进入管理页面。
4. 打开“数据与日志 → 日志”，确认没有不断重复的启动异常。
5. 暂时保留 AstrBot 运行，不要关闭这个进程。

如果你使用的是别人安装好的服务器，联系管理员确认版本和你的管理权限即可，不要把桌面客户端再装到远程服务器上来替代正在运行的实例。

官方桌面说明：<https://docs.astrbot.app/deploy/astrbot/desktop.html>。

## 3. 先接通消息平台

如果你已经能在目标聊天软件里给机器人发消息，并收到 AstrBot 的回复，直接进入第 4 节。

### 3.1 QQ 官方机器人与 OneBot，选你正在使用的那一种

QQ 官方机器人由 QQ 官方平台提供接入。普通 QQ 个人账号通过 NapCat 等 OneBot v11 实现端连接 AstrBot，则是另一种方式。二者的账号、配置和收到消息的范围不同。

尤其是“在群里不用 @ 就主动参与讨论”：插件只能分析平台实际投递给 AstrBot 的消息。部分 QQ 官方机器人配置只接收特定事件、被 @ 的消息或经授权的消息，插件不能把未投递的聊天记录凭空读出来。需要根据平台权限核对；不要仅因为开启了插件的“主动回复”就保证它能看到全群每一条消息。

### 3.2 使用 QQ 官方机器人

官方配置入口可能调整，完整注册与扫码授权按 AstrBot 的 QQ 官方机器人文档进行：

- 总入口：<https://docs.astrbot.app/platform/qqofficial.html>
- WebSockets：<https://docs.astrbot.app/platform/qqofficial/websockets.html>
- Webhook：<https://docs.astrbot.app/platform/qqofficial/webhook.html>

按官方文档创建并启用对应适配器，授权你自己的机器人，确认事件订阅与权限后，把机器人加入你有管理权限的测试会话。完成后先发 `/help` 或你已启用的 AstrBot 内置指令。

你应当在 AstrBot 日志看到收到的消息，并在聊天端看到回复。若平台只允许被 @ 时回复，就先 `@机器人 /help` 验证。先解决这一层连接，再安装战绩功能。

### 3.3 已安装 NapCat：在 AstrBot 创建 OneBot v11

如果你还没有 NapCat，不要凭本节猜测安装包和扫码入口。先阅读 NapCat 项目官方说明，按当前操作系统安装并完成账号登录：<https://napneko.github.io/>。AstrBot 对接说明是 <https://docs.astrbot.app/platform/aiocqhttp.html>。

两边均已启动后：

1. 打开 AstrBot 管理页面。
2. 单击左侧“机器人”。
3. 单击“创建机器人”或同义的新增按钮。
4. 消息平台类别选择 `OneBot v11`。
5. `ID` 填 `wows_qq`，用于区分这个连接，不是游戏 ID。
6. 勾选“启用”。
7. “反向 WebSocket 主机地址”填 `0.0.0.0`。它表示 AstrBot 在自己的设备上监听连接，不是给 NapCat 填的目标地址。
8. “反向 WebSocket 端口”先保留 `6199`。如果已被其他程序使用，改成一个空闲端口，并在下一步两边保持一致。
9. 如果你在 NapCat 配置了 Token，在这里填同一份 Token；不相同会连接失败。不要把 Token 发到群里。
10. 单击“保存”。

### 3.4 在 NapCat 配置反向连接

1. 打开 NapCat 自己的 WebUI。具体地址看 NapCat 当前启动日志，不要把 AstrBot 管理页面误当成 NapCat 页面。
2. 进入“网络配置”。
3. 选择“新建”。
4. 选择 `WebSocket 客户端` 或“反向 WebSocket”，不要选成让 AstrBot 主动连接的正向服务端。
5. 勾选“启用”。
6. URL 按实际部署方式填写：
   - 两者都直接装在同一台 Windows 电脑：`ws://127.0.0.1:6199/ws`。
   - AstrBot 与 NapCat 在同一 Docker 网络，AstrBot 服务名为 `astrbot`：`ws://astrbot:6199/ws`。
   - NapCat 在容器、AstrBot 在 Windows 宿主机：需要填从该容器可访问的宿主机地址。Docker Desktop 常用 `ws://host.docker.internal:6199/ws`，并检查 AstrBot 监听地址与防火墙。
7. URL 最后必须有 `/ws`。不要把 `0.0.0.0` 填为客户端目标地址。
8. 若界面提供消息格式，选择消息数组 `Array`；若有 Token，填与 AstrBot 相同的值。
9. 保存配置，等待重新连接。
10. 回到 AstrBot“数据与日志 → 日志”，观察是否出现 OneBot v11 适配器已连接的消息。
11. 用另一个真实聊天账号给机器人发 `/help`。确认收到回复后，再测试群聊。

若日志显示连接后立刻关闭，依次检查 URL、端口、`/ws`、Token 和网络位置。容器里的 `127.0.0.1` 指容器自己，不会自动指向另一台设备。AstrBot 和 NapCat 的管理端口只在必要范围开放，不需要为了接通而把所有端口暴露到公网。

## 4. 给自己设置管理员权限

开启/关闭主动回复等管理命令需要 AstrBot 管理员权限。

1. 在机器人能收到的聊天里发送 `/sid`。这是 AstrBot 内置指令；如果你的安装没有启用对应内置指令扩展，请到“插件 → 管理行为 → 指令”查看可用指令，或在收到消息的日志里查看发送者 ID。
2. 记下你本人账号的发送者 ID。不要填机器人的账号 ID，也不要把游戏 account_id 当成聊天账号 ID。
3. 打开 AstrBot 管理页面的设置/配置文件。
4. 找到当前会话使用配置中的管理员 ID 设置，把你的聊天账号 ID 添加进去。不同版本可能位于“其他配置”或平台相关配置中，可用页面搜索查找“管理员”。
5. 单击保存。
6. 重新发一个需要管理员权限的指令验证。若仍提示无权限，确认这个会话实际使用的是刚才修改的那份配置，以及 ID 是否带有平台要求的前缀。

不要为了方便把群里所有人都设为 AstrBot 管理员。普通用户绑定、查战绩和查看攻略不需要管理员权限。

## 5. 安装本插件

### 5.1 从 GitHub 仓库安装

1. 打开 AstrBot 的管理页面。
2. 单击左侧“插件”。
3. 若顶部有多个标签，选择“插件”，再进入“已安装”。
4. 找到右下角“安装插件（+）”。有些版本把按钮放在顶部，功能相同。
5. 单击“从链接安装”。
6. 在仓库地址一栏粘贴下面这一整行：

   ```text
   https://github.com/brochure325/1
   ```

7. 确认地址末尾是仓库名 `1`，没有 `/blob/`、`/tree/`、`README.md` 或本指南文件名。
8. 确认安装来源并点击安装。
9. 等待下载与依赖安装结束。安装依赖时不要反复点击安装。
10. 回到“已安装”，找到 `astrbot_plugin_wows_captain` 对应的战舰世界舰长插件。
11. 确认开关已经打开，没有出现在“加载失败插件”中。
12. 若出现加载失败，先点开错误文字或日志。最常见的是网络导致依赖没有安装完成，第 15 节给出修复方式。

成功标准是“插件已安装并已加载”，不是“浏览器能打开 GitHub”。运行 AstrBot 的服务器也需要能访问 GitHub 和 Python 依赖源。

### 5.2 仓库下载不了：使用 ZIP 安装

如果浏览器能访问 GitHub、AstrBot 设备却不能直接下载仓库，可这样做：

1. 在浏览器打开 <https://github.com/brochure325/1>。
2. 单击仓库文件列表上方的绿色 `Code` 按钮。
3. 选择 `Download ZIP`。
4. 等待 ZIP 下载完成，记住浏览器下载位置。
5. **先不要解压**，回到 AstrBot 管理页面。
6. 进入“插件 → 已安装 → 安装插件（+）”。
7. 选择“从文件安装”。
8. 点击选择文件，在“下载”文件夹中选中刚才的 `.zip`。
9. 确认上传并安装。
10. 安装完成后检查加载状态，再继续填写配置。

ZIP 内应当是完整项目，包含 `main.py`、`metadata.yaml`、`requirements.txt`、`core`、`knowledge` 等内容。只上传一个 `.py` 或把网页“另存为”成 HTML 都不能安装插件。ZIP 安装仍可能需要联网安装依赖。

不需要同时执行 5.1 和 5.2。重复安装可能出现两个同功能插件或目录冲突；先在“已安装”里确认现有状态。

官方插件管理说明：<https://docs.astrbot.app/use/plugin.html>。

## 6. 申请自己的 Wargaming application_id

### 6.1 登录开发者门户

1. 在浏览器打开 <https://developers.wargaming.net/>。
2. 确认域名是 `developers.wargaming.net`。
3. 找到登录入口，使用你自己的 Wargaming 国际账号登录。
4. 登录时按你的账号所属地区选择区域，完成官方要求的验证。
5. 进入 `My applications`，也可打开 <https://developers.wargaming.net/applications/>。

如果你只有国服账号，可能无法直接在这里登录。先按 Wargaming 的国际账号注册流程准备可用账号，不能通过把国服昵称填进密码框来解决。

### 6.2 创建应用并复制 ID

1. 在 `My applications` 页面找到 `Add application`。
2. 输入一个你容易识别的应用名称，例如 `My WoWS AstrBot`。
3. 应用类型根据你的实际部署方式选择。个人本地用途可按门户当前说明选择 standalone；服务器应用按 server 方式填写要求的网络信息。不要把临时示例 IP 当成你的服务器出口 IP。
4. 若页面要求站点、回调地址或允许 IP，查看旁边的官方说明，填写自己的实际信息；本插件读取公开战绩不需要你把游戏登录重定向给机器人。
5. 单击添加/创建。
6. 在创建后的应用信息中找到 `application_id`。
7. 复制完整值，不带空格或换行。
8. 只把它填入下一节的 `wg_application_id`，不要发到群里。

不要填 `demo`、你的昵称、玩家数字 ID、模型 API Key 或浩舰 Cookie。这几种值用途不同。Wargaming 的演示应用访问已经停止，使用自己的 ID 才能实际查询。

官方申请说明：<https://developers.wargaming.net/documentation/guide/getting-started/>。

### 6.3 验证 ID 是否可用

完成第 7 节配置后，执行 `/wows 搜索 asia 你的真实昵称`。如果返回一个或多个真实玩家结果，说明应用 ID、网络和对应区域至少完成了一次有效查询。

若提示 `INVALID_APPLICATION_ID`，重新复制应用 ID；若是 `INVALID_IP_ADDRESS`，检查你申请的 server 应用是否限制了出口 IP；若是频率限制，等待后重试，减少大量查询和采样频率。不要用公开论坛里的陌生应用 ID 代替自己申请。

## 7. 填写插件配置

### 7.1 打开配置与保存

1. 回到 AstrBot“插件 → 已安装”。
2. 在本插件卡片上找到齿轮图标或“配置”。
3. 单击打开插件参数。
4. 按下面说明填写。
5. 单击“保存”。如果界面提示需要重载，确认后重载这个插件。
6. 保存后再进入一次配置，核对关键字段没有因为未保存而丢失。

新手第一轮只需要填 `wg_application_id`，把 `default_region` 选对，其余先按默认。之后配置聊天模型和主动会话范围。

### 7.2 每个字段填什么

**`wg_application_id`**：填写第 6 节申请的 Wargaming 应用 ID。留空时，依赖官方战绩 API 的功能无法查询。插件设置把它作为凭据保存，不需要写进代码。管理员也可在服务端通过 `WOWS_WG_APPLICATION_ID` 环境变量提供；初次安装只选一种方式即可。

**`default_region`**：填 `asia`、`eu` 或 `na`。大部分亚服玩家选 `asia`。查询本人时优先使用绑定记录的区域；某些未绑定的入口用它作为默认区域。搜索、绑定或显式指定另一玩家时，仍按命令格式填写区域，不要因为设置过默认值就删掉必填参数。

**`chat_provider_id`**：选择 AstrBot 中已经存在的聊天模型提供商。若显示下拉选择器，直接选对应项；若使用 JSON 配置，填写该提供商 ID。留空时跟随当前会话可用的提供商。这里不是厂商 API Key，也不是模型网页网址。

**`vision_provider_id`**：用于截图分析的视觉模型提供商 ID。留空时尝试跟随当前会话；如果当前模型没有图片输入能力，请先新增视觉模型，再把它的提供商 ID 填到这里。

**`auto_reply_enabled`**：主动参与战舰世界话题的总开关，默认开启。需要只用手动命令时可以关闭；之后管理员也可通过 `/wows 主动 开` 或 `/wows 主动 关` 调整当前会话行为。

**`auto_reply_sessions`**：允许主动讨论的会话 UMO 列表。空列表表示允许插件处理所有它实际收到的会话消息。第一次试用建议只加入测试群的 UMO，再逐步扩大，避免在不需要的群里参与讨论。

**`discussion_cooldown_seconds`**：同一会话普通主动讨论的冷却时间，默认 `120` 秒。明确的游戏疑问不受这段普通讨论冷却限制；已有分析正在进行时也不会为同会话重复排队。它不影响你正常发查询命令。不要把它设得很小来弥补平台消息没投递的问题。

**`snapshot_interval_minutes`**：对已绑定玩家的自动快照采样间隔，默认 `60` 分钟。Bot 需要持续在线且能访问 API 才能积累。若绑定人数很多，适当增大间隔可降低 API 请求量。

**`haojian_cookie_env`**：保存浩舰会话的环境变量名称，默认 `WOWS_HAOJIAN_COOKIE`。这里填“变量名”，不是直接粘贴 Cookie。匿名查询能用时先保留默认即可。

**`haojian_cookie_file`**：可选的服务端私有会话文件绝对路径。留空表示不使用文件方式。如何保存本人会话请看 [浩舰接入](浩舰接入.md)，不要在仓库中新建包含 Cookie 的文件。

**`font_path`**：图表中文字体文件的绝对路径。Windows 通常可自动找到系统中文字体，先留空；Linux/Docker 出现乱码或方框时按第 14 节处理。字体应是实际存在的 `.ttf`、`.ttc` 或可被绘图库读取的字体文件。

**`kokomi_bridge_url`**：可选的 Kokomi 桥接服务地址。只使用本插件原生查询时留空。需要把 Kokomi 原有命令接入时，先部署并授权桥接服务，再填它的地址；不要填 Kokomi 项目主页或普通网页地址。

**`kokomi_token_env`**：保存 Kokomi 桥接令牌的环境变量名称，默认 `WOWS_KOKOMI_BRIDGE_TOKEN`。仅桥接模式需要，令牌本身放在服务端环境变量里，不要在群里发送。

**`kokomi_platform`**：Kokomi 上游授权平台标识，默认 `qq_bot`。仅桥接模式需要，应与获授权的后端配置一致；不使用桥接时保留默认。

### 7.3 确认当前会话确实允许使用本插件

1. 打开 AstrBot 的配置文件管理。
2. 找到你的聊天平台/测试群实际使用的配置文件。
3. 在“插件”范围设置中确认允许本插件，或保持“全部已启用插件”的默认范围。
4. 若你给不同群分配了不同配置，分别核对目标群。
5. 保存。

“插件卡片已打开”和“当前会话允许这个插件”是两个设置；只在另一份配置中勾选不会影响当前群。

## 8. 接入聊天模型与视觉模型

### 8.1 配置聊天提供商

AstrBot 可以连接多种厂商。使用你已经有权限使用的服务，具体 URL、Key 和模型名称从服务商自己的控制台复制，本文不提供虚构的通用 Key 或保证可用的免费额度。

1. 打开 AstrBot 管理页面。
2. 进入“模型提供商 → 对话”。
3. 单击“新增”。
4. 选择你的服务商实际支持的接口类型。例如服务商明确说明兼容 OpenAI API 时，选择 `OpenAI Compatible`。
5. 给提供商起一个便于区分的 ID/名称，例如 `wows_chat`。
6. 在 API Base URL 填服务商官方文档给出的完整地址。不要照搬其他厂商的 `/v1` 路径。
7. 在 API Key 填你自己的有效 Key；不要填 WG 的 `application_id`。
8. 选择或填写模型名称，注意模型名称通常要完全匹配服务商支持的字符串。
9. 保存。如果界面有测试连接，执行测试并确认成功。
10. 在当前会话使用的配置中选中这个聊天模型，或把提供商 ID 填到本插件 `chat_provider_id`。
11. 回到聊天，执行 `/wows 分析 驱逐舰开局如何判断能不能抢点，请结合已知条件给判断步骤`。

你应当看到模型生成的分析，以及可用资料中的来源。`/wows 攻略 问题` 则可直接检索随包知识，不需要用它验证模型连接。若分析命令提示“未配置模型”，检查的是 AstrBot 提供商与当前会话配置，不是去更换游戏账号。

模型配置入口说明：<https://docs.astrbot.app/providers/start.html>。

### 8.2 配置视觉模型

1. 在模型服务商控制台确认你选的模型明确支持图片输入；“可以生成图片”不等于“可以看图片”。
2. 在 AstrBot 添加或使用一个支持图片的对话提供商，按上一小节填写对应接口、Key 和模型。
3. 在本插件配置里把 `vision_provider_id` 填为这个提供商 ID；如果当前聊天模型本身支持图片，也可保持为空使用当前提供商。
4. 在聊天里发送一张清晰的战绩图，附文字 `/wows 分析 帮我分析这张图，先核对样本和模式`。
5. 如果平台把文字和图拆为不同消息，可先发图，再用“回复/引用”这张图片发送分析命令；不同消息适配器对引用图的支持范围不同。
6. 检查回答是否提到了图上真实存在的玩家、样本、模式和数字。识别错字时先纠正关键值，再让它继续分析。

如果图片太糊、被压缩或没有显示完整时间范围，Bot 应要求补齐关键内容，不能从一张胜率图断言你每局的走位。发送原图和必要的对局背景更有效。

### 8.3 费用与用量

手动查询官方数字、绘制本地图表和读取本地攻略，不必每次调用聊天模型；自然语言分析与主动讨论会消耗模型调用额度。图片输入通常也计费用，具体算法由模型服务商决定。

开始时先把主动回复限制在一个测试群，保留 120 秒冷却，在模型控制台设置你能接受的额度或预算提醒。不要让多个重复安装的插件同时回复同一话题。

## 9. 用一组最小命令完成验收

下面代码中的“你的昵称”需要替换成你自己的真实游戏昵称。尖括号说明和示例中文不是必须照抄的参数；先一次只发一条，看到结果再进行下一条。命令使用默认 `/` 前缀，如果你把 AstrBot 前缀改为 `!`，对应改为 `!wows`。

### 9.1 验证插件响应

1. 在已经接通的私聊或测试群发送：

   ```text
   /wows 帮助
   ```

2. 你应当收到本插件帮助。如果没有任何消息，先看 AstrBot 日志是否收到了这条消息，再看插件开关和当前会话权限。
3. 继续发送：

   ```text
   /wows 状态
   ```

4. 查看绑定、WG 应用 ID 配置、知识条目、快照任务和主动讨论状态。该命令也会返回“本会话 ID”，后面配置会话范围时可以直接复制。状态检测成功不表示所有第三方服务或模型都完成了实际请求，下一步仍需真实查询。

### 9.2 搜索并绑定自己

亚服：

```text
/wows 搜索 asia 你的昵称
/wows 绑定 asia 你的昵称
```

欧服和美服分别把 `asia` 改成 `eu` 或 `na`。

如果昵称里有空格，按帮助给出的引号方式输入，或先搜索后复制返回的数字 account_id 来绑定，避免昵称歧义。例如下面的“数字ID”应换成你刚查到的真实数字：

```text
/wows 绑定 asia 数字ID
```

确认绑定结果里的地区与昵称都正确。绑定是“这个聊天账号默认查询哪个公开游戏档案”，不是登录游戏，也不能证明你拥有这个游戏账号。不要用它进行账号交易或身份认证。

绑定按“当前会话 + 发言者”保存。你在私聊绑定过，并不代表去另一个群也已经完成绑定；换会话时如提示未绑定，在那个会话重新绑定即可。

### 9.3 查询战绩和单船

```text
/wows 战绩
/wows 单船 大和
/wows 船池
/wows 舰种 bb
```

你应当看到真实统计与可用图表。`bb` 是战列舰，驱逐舰常用 `dd`、巡洋舰 `ca`、航母 `cv`、潜艇 `ss`；以 `/wows 帮助` 的当前支持值为准。

没有开过大和时，单船查询提示没有战斗记录是正常结果。改查你真正开过的舰船，不要为了“让图出来”虚构战绩。

可显式查看另一公开玩家：

```text
/wows 战绩 asia 数字ID
/wows 单船 大和 asia 数字ID
```

玩家隐藏了统计时，插件会说明无法读取，不会绕过玩家隐私设置。

### 9.4 选择统计模式

默认随机战与单排、双排、三排、排位、军团战不能混作同一个能力结论。你可以在战绩命令末尾指定模式，例如：

```text
/wows 战绩 --mode pvp
/wows 战绩 --mode pvp_solo
/wows 战绩 --mode pvp_div2
/wows 战绩 --mode pvp_div3
/wows 战绩 --mode rank_solo
/wows 战绩 --mode clan
```

其中 `pvp` 为接口提供的随机战总项；其他模式是否有数据取决于官方接口和账号记录。排位/军团字段缺失时不等于玩家没参加，也不应自动填零。若某版本官方接口没有暴露你要的模式，以提示为准，不能用随机战冒充。

## 10. 近期战绩、趋势与排行榜怎么用

### 10.1 第一天安装没有七天历史，属于正常情况

本插件原生近期依靠自己保存的真实累计快照做差值，不能在第一天凭空还原安装前七天的逐场记录。

1. 绑定玩家后执行一次 `/wows 战绩`，建立当前数据基线。
2. 保持 Bot 在线，并确认采样间隔配置，例如每 60 分钟一次。
3. 去游戏里完成若干场战斗。
4. 等待官方 API 更新并让插件再次采样；官方统计更新可能有延迟。
5. 执行：

   ```text
   /wows 近期 7
   /wows 趋势 30
   ```

6. 阅读输出的真实覆盖起止时间。只有两天样本时，它只能分析这两天，不能因为命令写了 7 就变成完整七天。

电脑关机、Bot 离线或 API 长期访问失败会留下采样缺口。快照差值是这段实际覆盖区间内的汇总，不是每一局的详细战斗日志。需要已存在的服务端近期历史时，配置对应 Kokomi 授权桥接服务，见 README 中的桥接文档。

### 10.2 排行榜的范围

本插件原生榜单是**当前会话已绑定玩家组成的候选池**，按同一服务器和同一艘船比较。它不会把一个群里的十个人叫成“亚服前十”。

1. 让测试群里准备参与的玩家各自完成绑定。
2. 确认他们在同一地区，且有目标舰船的有效记录。
3. 发送：

   ```text
   /wows 排行 大和
   /wows 排行 大和 --sort avg_damage --min 20
   /wows 排行 大和 --sort win_rate --min 50
   ```

4. 查看图表注明的候选范围、最低场次和排序指标。

样本很小的玩家可能被最低场次过滤；同一玩家重复绑定不会让他合理变成两个独立参赛者。比较胜率前也要看单排/组排、版本和样本范围。

需要 Kokomi 原有的完整排名和它自己的数据口径时，先完成 [Kokomi 接入](Kokomi接入.md) 的桥接服务配置，再使用 `/wws` 原始命令；不要把未授权服务地址随意填进配置。

## 11. 浩舰舰船资料：先匿名查询，再按需登录

1. 发送：

   ```text
   /wows 浩舰 大和
   ```

2. 找到搜索结果中的舰名、数据版本和 `index`。
3. 用明确编号查询，例如：

   ```text
   /wows 浩舰详情 PJSB018
   /wows 浩舰详情 PJSB018 主炮
   /wows 浩舰详情 PJSB018 船体与隐蔽
   /wows 浩舰详情 PJSB018 全部 --page 1
   ```

4. 查看来源链接和版本。需要完整原始参数时，保存 Bot 提供的 JSON 文件。若当前聊天平台不支持文件传送，按提示由管理员从 Bot 设备取得导出文件，或直接打开原网页核对。
5. 发送 `/wows 浩舰状态` 查看是否匿名访问、是否配置 Cookie 以及站点是否确认了会话。

本项目已完成匿名真实在线查询测试，很多资料无需登录即可用。若你确实需要账号权限，请按 [浩舰接入](浩舰接入.md) 操作。指南写到了如何在浏览器中本人登录、获取会话、在 Windows/Docker 上私有保存和检查失效情况。

不要在聊天中发送“我的浩舰密码是……”或让群友代填 Cookie。插件不会替你购买会员、绕过验证码或读取账号无权访问的数据。

## 12. 攻略、战绩分析与对局复盘

### 12.1 查询攻略

```text
/wows 攻略 巡洋舰什么时候应该转场而不是继续守岛
/wows 攻略 驱逐舰面对雷达船如何确定安全点位
/wows 攻略 战列舰如何形成交叉火力
```

插件会检索随包攻略和允许接入的资料。问到版本敏感的消耗品距离、装填、赛事限制时，应结合浩舰或实际赛事来源；老版本原则不能自动当作当前版本硬参数。

内置知识不是“冠军身份认证”，也不能把一份文档当成十年实战经验的等价物。它的用途是按证据组织高水平分析，给你能在下一局尝试的选择与复盘方法。

### 12.2 分析自己刚查出的战绩

先执行 `/wows 战绩` 或 `/wows 单船 舰名`，再发送具体问题：

```text
/wows 分析 我最近驱逐舰伤害涨了但胜率没涨，应该先查什么
```

可补充你主要玩的模式、舰船、样本时间和想改进的目标。Bot 应将“图表里可观察到的事实”“可能原因”“还需要验证的对局行为”分开，例如场均伤害上涨可能来自目标选择、输出时机或舰船变化，仅凭平均值不能判定一定是后排刷伤害。

如果分析别人的图，先说明这张图对应哪个玩家、服务器和时间范围。将图中数字与官方数据不一致的地方先核对，再做训练建议。

### 12.3 用截图分析

1. 在游戏或水表机器人里打开完整战绩图。
2. 保存清晰原图，保留玩家、模式、场次和时间区间；可遮住不相关的个人信息。
3. 在聊天里上传图片，同时发送 `/wows 分析 先读取图中数据，再分析瓶颈`。
4. 或用聊天软件的回复功能引用图片，再发送同一命令。
5. 看 Bot 读到的数据是否与原图一致。小数字识别错误时，直接更正，不要把后续分析当成已经证实。

本功能要求视觉模型和消息平台支持图片取得。引用消息里只带一段“[图片]”而没有可用图像内容时，需要重新上传原图。

### 12.4 复盘具体战局

`/wows 复盘 你的具体战局问题` 会结合当前绑定玩家的公开战绩与文字/图片进行分析，因此先完成绑定。只分析文字或图片而不读取本人战绩时可用 `/wows 分析 问题`。尽量按这个顺序描述：

1. 地图、模式、你开的船与出生侧。
2. 关键时间或剩余时间、双方比分和占点状态。
3. 双方还活着的主要舰船、已知最后位置、雷达/水听/航母威胁。
4. 你当时的位置、血量、朝向、装填和消耗品状态。
5. 你做了什么、犹豫的另一种选择是什么。
6. 如果有小地图截图、录像或关键时段描述，一起提供。

例如“还剩六分钟、我们领先两百分、我方两艘驱逐一艘战列，敌方两艘战列守家，我是否需要追出去”比“队友都是废物为什么又输了”更容易得到可靠战术判断。你可以先吐槽，再补充当时情境；Bot 会接住情绪，也会把你能控制的选择讲清楚。

不要上传含他人隐私的完整聊天日志来代替游戏录像。当前插件不声称能直接解析任意版本的 `.wowsreplay` 二进制文件并还原全局视野；有文字、截图和关键片段时按这些证据分析。

## 13. 打开主动参与讨论

### 13.1 在测试群验证

1. 确认你已按第 4 节成为 AstrBot 管理员。
2. 在测试群发送：

   ```text
   /wows 主动 状态
   /wows 主动 开
   ```

3. 在插件配置里确认 `auto_reply_enabled` 开启。
4. 如果 `auto_reply_sessions` 不是空列表，确认测试群 UMO 已加入。
5. 明确疑问可以即时测试；测试普通讨论/吐槽时，等待上一条普通插话的冷却结束，默认 120 秒。
6. 用正常消息提出明确的战舰世界问题，例如：“战舰世界这局我开驱逐，点里有雷达船，开局还应该抢点吗？”
7. 不用 @ 的测试是否成功，取决于平台是否将这条普通消息投递到 AstrBot；在日志中核对收消息记录。
8. 收到回答后，继续测试一条讨论或吐槽。不要短时间连发十条来判断它是否正常。

插件使用消息事件参与讨论，不会扫描电脑里所有历史日志，也不会读取机器人没加入的群聊。“日志里有游戏话题”应当理解为 Bot 实际收到的会话话题，不能把系统报错日志或私密文件当成群消息来源。

### 13.2 怎样填会话 UMO

UMO 是 AstrBot 对一个具体群聊/私聊来源的统一标识，不总是只有一个 QQ 群号。

1. 在目标群发送 `/wows 状态`，找到返回的“本会话 ID”。
2. 复制它的完整值，不自行拼接猜测前缀。
3. 打开插件配置 `auto_reply_sessions`。
4. 如果界面提供会话选择器，可直接选择刚才那个测试群；否则按列表编辑器“添加”新增一项，粘贴该 UMO。
5. 不要把多个 UMO 用中文逗号塞在同一项里，也不要只填群号而漏掉平台和消息类型部分。
6. 保存后重载插件，再在该群执行 `/wows 主动 状态`。

若当前版本没有在你使用的界面显示 UMO，先让管理员通过实际消息事件确认标识，不要用看起来相似的机器人 ID 代替。空列表能用于短时测试，验证后再限定范围。

### 13.3 控制参与频率与关闭

群里需要安静时，管理员发送：

```text
/wows 主动 关
```

需要停止所有会话的自动参与，在插件设置里关闭 `auto_reply_enabled` 并保存。手动战绩查询仍可继续使用。

吐槽模式围绕游戏机制和具体对局展开，不需要攻击现实中的玩家身份，也不把“系统针对我”“队友必定故意送”当成有证据的结论。你提供越完整的战局，Bot 越能在吐槽后给出可执行建议。

## 14. 图表中文字体与显示问题

### 14.1 Windows 中文显示方框

1. 在聊天里先执行 `/wows 战绩`，确认能返回文字数据。
2. 图表中文若显示方框，打开 Windows 文件管理器。
3. 在地址栏输入 `C:\Windows\Fonts`，按回车，确认存在中文字体。
4. 常见可用字体文件为 `C:\Windows\Fonts\msyh.ttc`。只有文件实际存在时才填写这个路径。
5. 打开插件配置 `font_path`，填字体文件的完整绝对路径并保存。
6. 重载插件，重新执行战绩命令。

不要在 Windows 里填写 Linux 路径；也不要把字体显示名“微软雅黑”当成实际文件路径。

### 14.2 Ubuntu/Debian Linux 安装中文字体

以下命令适用于你能管理的 Ubuntu/Debian 系统，其他发行版按自己的包管理器安装中文字体。

```sh
sudo apt-get update
sudo apt-get install -y fonts-noto-cjk
fc-match "Noto Sans CJK SC"
```

最后一条用于确认字体存在。若输出的字体路径不是你预期的文件，使用系统实际安装路径；常见路径为 `/usr/share/fonts/opentype/noto/NotoSansCJK-Regular.ttc`。将实际路径填到插件 `font_path`，重载后再测试图表。

### 14.3 Docker 中的字体

容器无法自动看见宿主机的 `C:\Windows\Fonts`。可以在镜像中安装字体，或将字体目录挂载进容器，然后填容器内的路径。

临时测试 Debian/Ubuntu 系镜像时，可由管理员执行：

```sh
docker exec -u 0 astrbot apt-get update
docker exec -u 0 astrbot apt-get install -y fonts-noto-cjk
```

此做法可能在重新创建容器后丢失。长期运行建议把字体作为镜像构建步骤，或放在持久目录并只读挂载。假设宿主机项目目录已有 `fonts/NotoSansCJK-Regular.ttc`，Compose 可增加：

```yaml
volumes:
  - ./data:/AstrBot/data
  - ./fonts:/opt/wows-fonts:ro
```

然后插件 `font_path` 填 `/opt/wows-fonts/NotoSansCJK-Regular.ttc`。保留原有 `volumes` 项，不要为了添加字体覆盖掉保存数据的挂载。字体来源与分发许可由管理员确认；没有字体文件时不要只创建一个空文件冒充。

### 14.4 能发文字却不能发图片/文件

先看日志里是绘图失败还是发送失败。绘图失败通常与字体、依赖、可写目录有关；发送失败通常与消息平台上传限制、图片文件路径或网络有关。平台不支持某类文件时使用文字摘要和原始来源链接，不要把“导出成功”误当成“已经发到群里”。

## 15. 安装失败和常见错误，按这一顺序处理

### 15.1 完全没有回复

1. 在 AstrBot“数据与日志 → 日志”里找这条消息。
2. 如果日志根本没收到，检查消息平台连接、账号状态和事件权限。
3. 如果收到但没执行，检查命令前缀、插件开关、当前配置是否允许插件。
4. 先发 `/wows 帮助`，不要一开始就用复杂的截图复盘。
5. 如果只有管理员指令失败，核对你的聊天发送者 ID 与管理员设置。

### 15.2 提示缺少 aiohttp、Pillow、matplotlib 等依赖

**如果出现 `Pillow<13 ... vs (constraint) pillow==13.0.0`：** 这是插件v1.0.0的依赖上限与Core固定版本冲突，已在v1.0.1修复。

1. 打开AstrBot管理面板，进入“插件→已安装”；若插件显示失败，到“失败插件”区域找到它。
2. 若卡片提供“更新”，先点更新，让仓库代码更新到v1.0.1；然后点“重试加载”或“重新加载”。单独重试旧代码仍会报同一个冲突。
3. 若失败卡片没有更新入口，从本仓库重新下载ZIP，在“从文件安装”中选择新包。如果面板提示已存在且不支持覆盖，使用下面的文件修改办法，保留配置与数据。
4. 找到AstrBot实际插件代码目录下的`astrbot_plugin_wows_captain/requirements.txt`（部分安装方式目录名为`1`）。把`Pillow>=11.2.1,<13`改成`Pillow>=11.2.1`，其余依赖保持原样并保存。不要修改AstrBot自身的约束文件。
5. 一并更新`metadata.yaml`中的`astrbot_version`为`'>=4.29.1'`，或直接采用v1.0.1仓库中的文件。源码接口已核对4.29.1与4.29.3，不需要仅为这个插件强制升级核心。
6. 回到管理面板重试加载，确认不再出现该冲突，再发`/wows 状态`。更新后的完整插件应显示版本1.0.1。

不要卸载或降级Core的Pillow 13.0.0，也不要禁用依赖保护。原生图表使用的API不需要旧版Pillow。

1. 打开失败插件详情，记录明确缺少哪个包。
2. 在 AstrBot“数据与日志 → 日志”页面寻找“安装 Pip 库”入口。
3. 优先按照本项目 `requirements.txt` 安装依赖，完成后重载插件。
4. Docker 环境必须安装到容器内 AstrBot 实际使用的 Python，不能只在 Windows 宿主机执行 `pip install`。

需要命令行修复时，先确认实际插件目录。本仓库名是 `1`，安装目录可能与显示名不完全相同；不要盲目假定路径。

```sh
docker exec astrbot ls /AstrBot/data/plugins
```

找到包含本插件 `main.py` 和 `requirements.txt` 的目录后，再执行下面命令，把 `实际插件目录名` 换成你刚看到的目录：

```sh
docker exec astrbot python -m pip install -r /AstrBot/data/plugins/实际插件目录名/requirements.txt
```

如果容器使用 `uv`、没有 `pip` 模块或 Python 命令不同，按你那份 AstrBot 镜像的运行环境处理，先使用 WebUI 依赖安装入口或官方部署说明。不要在系统里随便安装另一套 Python 来掩盖实际环境问题。

### 15.3 API 查询报错

- “没有配置 application_id”：回到插件齿轮填写 WG 应用 ID 并保存。
- “无效应用 ID”：检查是否复制完整、是否误填模型 Key 或玩家 ID。
- “无效 IP”：检查开发者应用的允许出口 IP 设置与服务器真实出口。
- “找不到玩家”：核对 `asia/eu/na`，尝试英文原昵称，或使用搜索返回的数字 ID。
- “玩家隐藏统计”：尊重隐藏设置，插件不能读取未公开战绩。
- “过于频繁”：减少重复命令与自动采样，等限制恢复后再试。
- 网络超时：检查 AstrBot 所在设备能否访问对应 `api.worldofwarships.asia`、`api.worldofwarships.eu` 或 `api.worldofwarships.com`，不是只检查你浏览器能不能打开游戏官网。

### 15.4 近期没有数据或数字看起来不对

1. 看实际快照覆盖时间，确认并非首次采样。
2. 核对统计模式，随机总项和单排不能直接对比。
3. 核对游戏是否刚结束，等待官方 API 更新。
4. 检查 Bot 是否整晚离线，或快照任务是否报网络错误。
5. 注意 API 计数可能调整；插件检测到累计值下降时不应算出负场次。
6. 如果更换账号或服务器，重新确认绑定目标，别把两个档案相减。

### 15.5 能查数据，不能分析图片

1. 检查 `vision_provider_id` 是否指向真实存在的 AstrBot 提供商。
2. 确认该模型支持图片输入，而不是只支持文本或图片生成。
3. 确认机器人实际取得了图片，引用消息并不保证所有平台会转交原图。
4. 上传清晰原图再试。
5. 在模型厂商控制台查看额度、权限与错误信息；删除凭据后再提供错误文字给维护者。

### 15.6 普通群消息不触发主动讨论

先检查平台有没有将它投递给 AstrBot；再检查话题识别、会话 UMO 白名单、总开关、会话开关与冷却时间。Bot 只会在识别到相关话题时按规则参与，不会每条带“船”字的聊天都插话。

如果日志里只有被 @ 的消息，问题在消息权限与适配器层。插件无法通过读取系统日志补齐未收到的群消息。

### 15.7 GitHub 或依赖下载超时

可以先使用 ZIP 安装，确认运行设备的外网和依赖源。AstrBot 的网络设置中提供 HTTP 代理和 GitHub 加速相关选项；只配置你信任且确实可用的服务。

Docker 内的 `http://127.0.0.1:7890` 指容器自己的代理端口，不会指向宿主机。Windows Docker Desktop 连接宿主机服务时通常需要 `host.docker.internal`，并确认该服务允许容器访问。不要把陌生人给的代理地址直接用于带 Cookie 或 Token 的请求。

## 16. 可选：用 Docker 长期运行

这一节是替代第 2 节的部署方式。已使用桌面版并能正常运行的用户，不必为了本插件额外安装 Docker。

### 16.1 Windows 准备 Docker Desktop

1. 打开 Docker 官方安装文档 <https://docs.docker.com/desktop/setup/install/windows-install/>。
2. 按文档确认你的 Windows 版本、虚拟化和 WSL2 条件。
3. 下载并安装 Docker Desktop，按安装提示完成所需重启。
4. 从“开始”菜单打开 Docker Desktop，等待它显示正在运行。
5. 按 `Win` 键，输入 `PowerShell`，打开 Windows PowerShell/终端。
6. 依次执行：

   ```powershell
   docker version
   docker compose version
   ```

7. 第一条应能看到客户端和服务端信息；如果只有客户端或提示无法连接 daemon，先启动 Docker Desktop。第二条应显示 Compose 版本。

不要在聊天窗口里输入这些命令。它们要在电脑的终端窗口中执行。本文没有替你验证具体电脑是否满足 Docker 安装条件，遇到 WSL/虚拟化问题请先按 Docker 官方说明解决。

### 16.2 建立固定工作目录

1. 打开文件管理器，在你方便管理的位置新建文件夹，例如 `C:\AstrBot`。
2. 进入这个文件夹。
3. 单击文件管理器上方地址栏，输入 `powershell`，按回车，在当前文件夹打开终端。
4. 先执行 `Get-Location`，确认显示的是 `C:\AstrBot`。
5. 创建一个名为 `compose.yaml` 的纯文本文件。可以用记事本新建，保存时“文件类型”选“所有文件”，文件名填 `compose.yaml`，编码选 UTF-8。
6. 在文件里粘贴：

   ```yaml
   services:
     astrbot:
       image: soulter/astrbot:latest
       container_name: astrbot
       restart: unless-stopped
       ports:
         - "127.0.0.1:6185:6185"
         - "127.0.0.1:6199:6199"
       environment:
         - TZ=Asia/Shanghai
       volumes:
         - ./data:/AstrBot/data
   ```

7. 保存后在文件管理器打开“查看 → 显示 → 文件扩展名”，确认不是 `compose.yaml.txt`。
8. 上述例子将管理端口绑定本机，只适合同电脑访问。如果 NapCat 在另一个容器，要让两者在同一 Docker 网络并使用容器服务名；如果在另一台设备，按你的网络边界配置访问方式，不要直接把管理端口全部公开。

### 16.3 启动并登录

1. 在 `C:\AstrBot` 的 PowerShell 中执行：

   ```powershell
   docker compose up -d
   ```

2. 等待镜像下载和容器启动。网络较慢时不要反复创建同名容器。
3. 执行：

   ```powershell
   docker compose ps
   docker compose logs --tail 100 astrbot
   ```

4. 看见服务运行后，在浏览器打开 `http://127.0.0.1:6185`。这个地址针对你电脑上按本例映射的管理页面；远程部署时应按你的安全访问方式连接远程设备。
5. 用启动日志显示的初始用户名/随机密码登录，并马上更改密码。不要使用网上旧教程提供的固定默认密码。
6. 从第 3 节继续配置消息平台，再安装本插件。

如果镜像下载失败，查看 AstrBot 官方 Docker 文档当前提供的网络说明：<https://docs.astrbot.app/deploy/astrbot/docker.html>。不要把下载报错误认为插件报错，因为此时插件还没有运行。

### 16.4 开关、更新与日志

在保存 `compose.yaml` 的同一个目录打开终端。

临时停止服务：

```sh
docker compose stop
```

重新启动已有服务：

```sh
docker compose start
```

需要下载更新镜像时，先按第 17 节备份数据，再执行：

```sh
docker compose pull
docker compose up -d
```

持续查看日志：

```sh
docker compose logs -f --tail 100 astrbot
```

按 `Ctrl + C` 退出查看日志，不会因为退出查看而自动停止后台容器。不要删除 `data` 文件夹来解决普通依赖错误，它存放着配置和业务数据。

本例不包含 NapCat 容器。若你需要同时部署，两者的官方 Compose 入口由 AstrBot OneBot 文档提供，先按那份文档处理共享网络与账号登录，再接回第 3 节；不要同时照抄两份名为 `astrbot` 的容器配置到两个不同目录运行。

## 17. 备份、更新、解绑与卸载

### 17.1 更新前备份

机器人数据包含绑定、快照、插件配置和可能的私有服务设置。更新代码不等于重建历史。

1. 先记录当前插件版本和 AstrBot 版本。
2. 暂停 AstrBot 或停止容器，避免复制 SQLite 数据库时恰好有写入。
3. 备份 AstrBot 的持久化 `data` 目录。Docker 按本文示例就是宿主机 `C:\AstrBot\data`；桌面版按客户端提供的数据目录入口查找。
4. 将备份保存在你自己的私有位置，文件名写上日期。
5. 不要把整个备份上传到公开 GitHub，它可能包含模型凭据、会话和登录资料。
6. 重新启动 AstrBot，再到插件卡片执行更新。

更新后重跑 `/wows 状态`、`/wows 战绩` 和一条浩舰查询，确认数据与功能正常。如果遇到需要迁移数据库的版本，先看仓库变更说明。

### 17.2 更换默认账号或退出绑定

更换账号时重新执行绑定，并认真确认服务器。停止关联时发送：

```text
/wows 解绑
```

解绑取消当前绑定关系，不代表向 Wargaming 删除你的公开档案，也不自动代表所有历史快照已经被销毁。需要删除本地历史数据时，先备份，再按项目的数据管理说明由管理员处理，不要直接删除整个 AstrBot 数据目录。

### 17.3 暂停与卸载

只想暂时不用：在插件卡片关闭开关即可；只不想自动插话：关闭主动讨论，保留手动查询。

确定卸载：在“插件 → 已安装”找到本插件，点击删除。仔细查看弹窗里的“同时删除配置”“同时删除持久化数据”选项；希望以后恢复快照时，不要把这些数据一起删除。

如果之前配置过浩舰 Cookie 或桥接令牌，卸载插件不会自动让网站登录失效。你可以在服务端删除相应私有环境变量/会话文件，并到对应网站退出或撤销会话。

## 18. 需要反馈问题时，提供哪些信息

在 <https://github.com/brochure325/1/issues> 提交问题前，先记录：AstrBot 核心版本、插件版本、部署方式（桌面/Docker/源码）、消息平台、你发送的具体命令、应该出现什么、实际出现什么、相关报错时间。

日志只截取错误附近的必要内容。公开前检查是否包含模型 Key、Cookie、Authorization、Token、管理密码、内网信息以及他人的私聊内容。图片应遮住与排查无关的个人信息，但保留错误文字和可复现条件。

“没有回复”时，一并说明日志有没有收到消息；“近期不完整”时，说明安装和首次采样时间；“图表乱码”时，说明字体路径与运行系统；“浩舰登录失败”时，提供状态结果中不含凭据的字段即可，绝对不要公开会话值。
