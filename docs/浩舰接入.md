# 浩舰舰船数据与登录会话接入

本文核对日期：2026-10-28。浩舰主页是 <https://iwarship.net/>，舰船数据库是 <https://iwarship.net/wowsdb/index>。不要把游戏账号密码交给机器人，也不要在群里发送浩舰密码、Cookie 或浏览器请求截图。

## 1. 先分清可以直接用的能力

插件直接读取浩舰现有网页使用的数据，支持当前目录中的中文名、英文名、简拼、内部编号（例如 `PJSB018`）以及 WG 数字舰船 ID 搜索。不会把某一艘船的参数硬写进代码。站点更新版本后，插件会重新发现当前版本。

2026-10-28 使用本插件的 Python/aiohttp 客户端完成了匿名在线验证：可以读取舰名目录、对比表和大和完整详情，所以**第一次使用可以不登录**。插件启动后，在聊天中发送 `/wows 浩舰 大和` 即可。如果能返回舰船资料，先保留这个最简单的配置。

继续发送 `/wows 浩舰详情 PJSB018` 可查询大和详情，其中 `PJSB018` 来自搜索结果。`/wows 浩舰状态` 检查站点与会话。详细分组和翻页方式以 `/wows 帮助` 为准。

站点当前真实数据包括船体、主炮、鱼雷、副炮、防空、舰载机、空袭、反潜、潜艇声呐、消耗品、弹道穿深和特殊机制。完整详情还包含可选模块、升级品、底层参数与消耗品组合。不同模块会保留多条记录，不能把其中一条当成所有配置的共同数值。

“所有舰船”指浩舰所选数据版本实际提供的舰船目录；插件不会承诺未公开测试舰、已删除舰或站点没有提供的隐藏数据。`ASIA` 是浩舰的 WG 正式版数据分支，`PT` 是 WG 测试版，`RU`、`RUPT` 属于 Lesta。测试服参数不代表正式服。国服是否同版本请在游戏内再次对照。

## 2. 资料来源与版本怎样判断

每次详情结果带有原始网页链接、浩舰数据版本和抓取时间。输出数值时以同一个版本、同一个模块配置为准。

插件缓存目录和详情一小时，避免连续查船重复向网站下载大文件。更改登录会话后会重新读取目录；重载插件也会清除内存缓存。没有把浩舰整站数据库放进 GitHub 仓库。

本次实际核对的网页与前端请求为：

- 入口 `/wowsdb/index`，页面内嵌 `serverVersion` 版本对象。
- 入口实际加载的脚本 `/wowsdb/static/js/wowsdb.js?v=20261008110019`。
- 舰名 `/wowsdb/data/ship-name/wg`。
- WG 对比表 `/wowsdb/data/get-ship-detail/{versionId}`。
- 单舰详情 `/wowsdb/detail/{versionId}-{舰船index}`，页面内嵌舰船 JSON。
- 官方站点使用说明：<https://iwarship.net/2020/07/05/how-to-database/>。

这些是站点自己的网页接口，并非网站对外承诺长期稳定的开放 API。插件会解析明确的 JSON，不执行网页里的 JavaScript。接口变动时会报告错误，不会把登录页误当成舰船数据。

## 3. 需要登录时，在浏览器完成真实登录

只有当所需内容确实要求登录，才需要以下步骤。插件支持复用你本人有权使用的登录会话；它不接管注册、验证码或付款。

1. 在自己信任的电脑上打开 Chrome 或 Edge 浏览器。
2. 在最上方地址栏输入 `https://iwarship.net/login/`，按回车。
3. 确认地址栏的域名是 `iwarship.net`。
4. 用你自己的浩舰账号完成登录；没有账号时先按网页的“注册”流程创建账号。
5. 如出现验证码，自己在网页完成。
6. 如需会员权限，先确认自己的账号已被网站授权使用所需功能；插件不会购买或绕过会员权限。
7. 在同一个浏览器窗口打开 `https://iwarship.net/wowsdb/index`。
8. 确认网页里能正常选船和查看你需要的数据。

## 4. 仅管理员获取本人的 Cookie

Cookie 相当于临时登录凭证。只放在 AstrBot 所在设备的私有设置中，不放进本项目代码、不提交 GitHub、不发给聊天模型或其他群成员。

以下步骤适用于桌面 Chrome / Edge：

1. 保持上一步的浩舰数据库页面打开。
2. 按键盘 `F12`；笔记本如果没有反应，试 `Fn + F12`。
3. 右侧或下方出现开发者工具后，单击顶部“网络 / Network”。如果看不到，单击顶栏的 `>>` 找到“网络”。
4. 在网页区域按 `Ctrl + R` 刷新，等待页面加载结束。
5. 在网络请求列表上方的筛选框输入 `index`。
6. 单击请求地址为 `https://iwarship.net/wowsdb/index` 的那一行，确认没有选中其他网站。
7. 单击右侧“标头 / Headers”。
8. 找到“请求标头 / Request Headers”，向下找到 `Cookie`。某些界面会将字段显示成小写 `cookie`。
9. 复制 **Cookie 后面的值**，例如 `某个字段=某个值; 另一个字段=另一个值`。不要复制整个请求，不要选“复制为 cURL”，也不要把网页发出来。
10. 如果没有 Cookie，请先确认登录确实完成，关闭开发者工具再按第 1 步重新进入。不能因为网页打开成功就假设已登录。

复制后下一步只做私有配置。不要在聊天框中运行诸如“设置浩舰Cookie …”的命令。

## 5A. Windows 本机运行 AstrBot：图形界面设置环境变量

如果 AstrBot 安装在云服务器或 Docker，跳到 5B。

1. 停止当前运行的 AstrBot，记住原来的启动入口。
2. 按键盘 `Win` 键，输入“编辑账户的环境变量”。
3. 单击搜索结果“编辑账户的环境变量”。
4. 在“用户变量”区域单击“新建”。
5. “变量名”填写 `WOWS_HAOJIAN_COOKIE`。
6. “变量值”粘贴刚才从浏览器复制的 Cookie 值。保持为一行，不加英文引号。
7. 单击“确定”，再关闭其余设置窗口。
8. 如果你通过终端启动 AstrBot，关闭旧的终端窗口，然后从原来的项目目录打开一个新终端。旧窗口可能不会读取新环境变量。
9. 重新启动 AstrBot。如果你用桌面启动器，完全退出启动器后再打开。
10. 进入 AstrBot 管理页面，找到本插件设置，确认 `haojian_cookie_env` 保持为 `WOWS_HAOJIAN_COOKIE`，保存。
11. 使用插件的“浩舰状态”命令检查，见第 6 节。

电脑上存在其他用户或以 Windows 服务运行时，AstrBot 可能使用另一个系统账号。请给实际运行 AstrBot 的账号设置环境变量；不要把 Cookie 填进公开截图。

## 5B. Docker Compose 运行 AstrBot：通过私有 .env 注入

这个配置位于你安装 AstrBot 的目录，**不是插件 GitHub 目录**。若现有文件含其他设置，保留它们，只添加下面内容。

1. 找到安装 AstrBot 时保存的 `docker-compose.yml` 或 `compose.yaml`。
2. 在它所在的文件夹打开文件管理器，先制作这份文件的备份。
3. 在同一个文件夹新建一个名为 `.env` 的文本文件。已存在 `.env` 时打开现有文件。
4. 用纯文本编辑器打开 `.env`，新增一行：

   ```dotenv
   WOWS_HAOJIAN_COOKIE='这里粘贴你自己的单行Cookie值'
   ```

5. 用实际 Cookie 替换中文文字，保留两侧单引号。不要把示例中文原样用于配置。
6. 保存并关闭。文件名必须是 `.env`，不能是 `.env.txt`；在 Windows 文件管理器里可先打开“查看 → 显示 → 文件扩展名”进行确认。
7. 打开 Compose 文件，找到 AstrBot 这个服务现有的 `environment:` 段；按该文件原来的列表或字典格式添加一个变量。常见列表形式如下，前面的缩进要与同段其他变量一致：

   ```yaml
   environment:
     - WOWS_HAOJIAN_COOKIE=${WOWS_HAOJIAN_COOKIE}
   ```

8. 如果原来已经有 `environment:`，只添加下面的那一行，不要再写第二个 `environment:`。如果原来是 `TZ: Asia/Shanghai` 这样的字典形式，则添加 `WOWS_HAOJIAN_COOKIE: ${WOWS_HAOJIAN_COOKIE}`，不要混用两种格式。
9. 保存 Compose 文件。
10. 在这个文件夹里打开终端，执行：

    ```sh
    docker compose up -d
    ```

11. 等待容器重新创建并启动。只点击旧容器的“重启”不一定会更新环境变量。
12. 打开 AstrBot 管理页面，检查插件设置中的 `haojian_cookie_env` 为 `WOWS_HAOJIAN_COOKIE`，保存。
13. 使用插件的“浩舰状态”命令检查。

如果使用宝塔、1Panel 或 NAS 容器管理器，也可在 AstrBot 容器的“环境变量”里增加同名变量，然后按管理器提示重新创建容器。不要把 `.env` 上传到 GitHub。

## 6. 验证会话，而不是只验证填了值

发送 `/wows 浩舰状态`。状态字段含义如下：

- `cookie_configured: true`：插件读取到了配置；这**不等于登录成功**。
- `authenticated: true`：当前网页明确给出了已登录收藏权限标记 `openCollection=true`，可据此确认本次请求具有相应会话。
- `authenticated: false`：站点给出了匿名标记，可能 Cookie 过期、复制不全或没有登录。
- `authenticated: null`：站点没有暴露可识别标记，插件不能确认身份；请直接在浏览器检查，不要当成成功。
- `detail_enabled: true`：入口页面开放详情功能，不代表账号拥有所有可能的数据权限。

随后查询一个你熟悉的舰船，对照网页版的同一数据版本和同一个模块。完整 JSON 结果带 `comparison` 和 `raw`：前者为对比参数，后者保留网页详情中的全部模块与参数。JSON 中的字段名和单位遵循原始来源，不能靠字段名相似就推断它们单位相同。

如果管理员更适合使用私有文件，也可将单行 Cookie 值保存到 AstrBot 服务进程可读的文件，随后在插件配置的 `haojian_cookie_file` 填该文件的绝对路径。文件必须位于插件 Git 仓库之外，例如 AstrBot 的私有数据目录；不要使用 `.py`、`.json` 代码文件，也不要把会话与普通舰船导出文件混放。环境变量有值时优先使用环境变量；删除旧变量后才会读取这个文件。容器里的路径应填写容器内已挂载的路径，不能直接照填宿主机的 Windows 路径。

## 7. 更新、过期与常见故障

- **浏览器能查，机器人说没有权限**：确认浏览器和服务器是否访问同一域名；按第 4 节重新复制本人有效会话，更新环境变量并重新启动运行进程/重新创建容器。不要把错误日志和 Cookie 一起发出。
- **HTTP 401 / 403**：检查登录与账号权限。不要尝试绕过验证码、付费限制或网站访问限制。
- **HTTP 302 / 其他跳转**：插件停止跟随，以免 Cookie 被发往不相关网站。自己在官网完成重新登录后更新会话。
- **HTTP 429**：网站限制频率。等待一段时间后再查，不要连续重启插件清缓存。
- **提示“找不到数据版本”或“详情页格式发生变化”**：站点结构可能更新。此时保留错误信息，去项目 Issues 反馈错误文字和网页公开链接，删除任何登录凭证后再发。
- **找到多个同名舰船**：用搜索结果里的 `index` 精确查询，避免混淆历史版、测试版或同名舰船。
- **图上数据与浩舰不同**：先核对游戏版本、基础/完全体模块、技能、升级品、加成与取整。不要把升级后的最小隐蔽和基础隐蔽放在同一列比较。
- **不再需要登录**：删除私有环境变量，重启 AstrBot；到浩舰网站退出会话。若 Cookie 曾经泄露，在网站撤销会话或修改密码，并重新登录。

## 8. 接入的实际边界

本插件已针对公开页面结构实现读取，并完成匿名真实在线验证；真实账号登录需要由你完成，发布时没有取得你的登录凭证，因此不宣称已经替你登录并完成账号联调。它读取服务器有权返回的内容，不绕过会员或访问控制。

本项目不拥有浩舰数据。提供原网页出处，按需使用并缓存；如用于公开服务或大量商业请求，请先向站点运营方确认授权和使用范围。
